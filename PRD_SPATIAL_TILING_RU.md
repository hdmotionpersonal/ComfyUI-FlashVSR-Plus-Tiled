# PRD: пространственный тайлинг FlashVSR+ T8

## Проблема

При обработке больших кадров пиковая VRAM для DiT и его активаций растёт с площадью изображения. Существующий `vae_tiled` делит только Wan VAE и не ограничивает пространственный размер основной модели.

## Цель и пользователь

Добавить в ComfyUI выборочный пространственный тайлинг FlashVSR+ для IMAGE и затем VIDEO, чтобы пользователь мог запускать большие кадры при ограниченной VRAM и управлять видом перехода между соседними тайлами.

## Пользовательский сценарий

Пользователь задаёт параметры в `FlashVSR+ Options`, соединяет её с `Upscale Frames`, включает тайлинг, выбирает размер тайла, overlap и Cosine, Linear или Gaussian. В `info` видит активный метод и сетку.

## Реализация на текущей ветке

- В существующую `FlashVSR+ Options` добавлены переключатель, размер, overlap и три метода смешивания.
- IMAGE обрабатывается по одному тайлу за раз; их float32 результаты смешиваются нормированными весами. Цветовая коррекция применяется после сборки.
- GPU-проверки ещё не проводились. Seed теперь задаёт общее пространственное latent-шумовое поле, из которого каждый тайл получает crop по глобальным координатам.

## Оставшийся объём первой версии

- Сетка строится в пикселях целевого модельного canvas и выравнивается по кратности 128.
- spatial tiling VIDEO; текущий переключатель влияет только на Frames/IMAGE.
- Три способа смешивания нормированной взвешенной суммой; сохраняются полные веса на внешней границе изображения.
- Проверить согласованность шума и результатов в overlap на GPU.
- Совместимость с существующим workflow без новой ноды: тайлинг выключен.
- Сохранить старые workflow с тайлингом выключенным по умолчанию.
- Сохранение точного crop/resize, размера, FPS, audio, trim и отмены.

## Не входит в первый этап

Объединение DiT предсказаний на каждом шаге денойзинга, обучение моделей для tiled-инференса, совместная обработка тайлов, произвольный размер каждого тайла, параллельный запуск на нескольких GPU и гарантия идентичности full-frame результату. Видео без временного spool и Wan VAE ограничиваются отдельной технической проверкой.

## Параметры

Начальные значения для экспериментов: tile 1024 px, overlap 128 px, Cosine, Gaussian sigma scale 0.25. Tile и overlap заданы на целевом canvas; tile кратен 128; overlap меньше половины tile. Эти значения не считаются оптимальными до GPU-сравнения.

## Критерии приёмки

1. Все режимы покрывают canvas без щелей; нормированное смешивание сохраняет тестовые константу и градиент, включая края и углы.
2. Отключённый режим и старые workflow сохраняют прежний путь обработки.
3. Фиксированный seed даёт согласованный шум на общих координатах соседних тайлов.
4. На GPU сравниваются швы и временное мерцание всех методов с untiled на согласованных входах.
5. VIDEO сохраняет число кадров, FPS, звук, trim и crop; отмена не публикует частичный файл.
6. Документированы реальные VRAM, RAM, время, временный диск и поддерживаемые модели/backend.

## Риски и решения

- Тайл меняет глобальный контекст внимания модели; blend уменьшает видимость границы, но не восстанавливает утраченный контекст.
- Независимый случайный шум соседних тайлов может дать разные структуры в overlap; нужен шум по глобальным latent-координатам.
- Полный RGB canvas в RAM неприемлем для долгого VIDEO; собирать bounded сегментами и измерить spool/память.
- Tiny и Wan VAE имеют разное поведение по временной памяти; публиковать ограничения отдельно.
- Модели и GPU-backend должны быть проверены отдельно для BF16, FP16 и INT8.

## Очерёдность

Tile geometry и blend kernels → CPU проверки → IMAGE → GPU оценка методов и seed/noise → Tiny VIDEO → документация и выпуск. Подробная инженерная разбивка и источники: `../SPATIAL_TILING_PLAN_RU.md`.
